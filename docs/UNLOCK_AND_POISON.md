# 解锁与 poison：判据、处置与防护

适用范围：NVIDIA GA100 CMP 170HX（`10de:20c2`）的电压毛刺解锁与 FF 熔丝烧写。本文给出**判据、处置顺序与概率模型**，以及每条判据在代码中的落地位置。原理（熔丝阵列分区、FF 记录语义、`SBFE`/`DSOV`/`CMD_SENSE` 的因果、注入方式与上游差异）见 [../README.md](../README.md) §1；寄存器与命令实机值见 [../README.md](../README.md) §3；烧写规程以 ffcalc 仓库 `docs/BURNING.md` 为准；台架脚本与开火闸门见 [../bench/README.md](../bench/README.md)。

## 一、物理模型

机制模型的原始出处是 [kate 的毛刺解锁长文](https://blog.kate.land/posts/using-voltage-glitching-to-unlock-the-a100/)（无 RTL，全部是从控制器状态、原始行可读性、option words 与 PRI 环可达性反推的黑盒假设，本文按"可复现假设"使用）。要点是：**毛刺改的是 boot 期的 sense/latch，不是熔丝本身**。启动阶段依次是 sense RIR → sense 控制行 → latch 控制行成 option words → sense 其余行 → latch 常规行 → 解析 FF 链 → latch FF 值；欠压脉冲打在"latch 控制行"这一瞬，行 0/1 的原始内容逐字节不变，变的只是它们派生出的 option words。这解释了窗口的三个性质：`CRC_STATUS` 仍是 `0x55`（阵列镜像没坏）、行 0/1 读回与毛刺前一致、任何一次重新 latch（`PEX_RST`、驱动加载、冷启）都会把它抹掉。

生产卡上 `SBFE=1` 只允许烧 FPF 区，且 `ENABLE_FUSE_PROGRAM` 恰好也是被 canary 关掉的、不可 shadow 的 option word。窗口之所以可用，是因为发一次 `CMD_SENSE` 后控制行派生的 option words 回到融合值、**唯独 `DSOV` 保持 0**：于是编程许可恢复，同时 shadow 通路仍开着，可以把 `SBFE` 影子写 0。`EFP_STATUS` 冷启后读 0、`CMD_SENSE` 后才为 1，是同一段因果的旁证。

FF（fuseless fuses，行 222–486）是"追加 + 后写覆盖整块"的脚本语义：某块的有效值是重放结果，追加记录只能让位变少（`new & ~old == 0`），写错的记录用新行纠正，不能擦除，但**行本身是一次性资源**。我们要解锁的 option words 几乎全在 FF 区。

写窗口是一个由两个位共同定义的状态：

| 位 | 偏移 | 窗口内读数 | 含义 |
|---|---|---|---|
| `DSOV_STATUS` | `0x00820084` | `0` | OTP 位 `OPT_DISABLE_SW_OVERRIDE`：为 1 时软件改写被禁止。它**不是电压比较器**，读 0 = 该位被采样成 0，软件可写 |
| `CRC_STATUS` | `0x00820070` | `0x55` | 阵列镜像校验仍完整（H0/H1 均通过） |

两者同时成立即俗称的 **Goldilocks**。毛刺的作用是在 boot 期 OTP 采样那一瞬把 NVVDD 拉低，使该位被读成 0，同时整块内容不被读坏（否则 CRC 变化，即 `over`）。上游把 `ENABLE_FUSE_PROGRAM` 在深故障态下读 0 解释成一种毛刺检测 canary：整行 sense 出错时，最安全的做法是先关掉最敏感的功能。

三个独立的物理维度决定结果：

| 维度 | 参数 | 作用 |
|---|---|---|
| 扰动深度 | `vd`（按 PMBus 码生效，LSB 6.25 mV） | 决定这一瞬读成 0 还是整块读崩 |
| 相位 | `delay`、`gap`（`first = td - delay`） | 决定下拉落在启动期的哪个时刻，只有与 OTP 采样时刻重叠才可能有效 |
| 累计能量 | `pulses × pw` | 同一深度下的第二独立致死维度 |

判决分五档（`host/ga100vfi/classify.py: attempt_outcome`，唯一判据函数）：

| 判决 | 条件 | 含义 |
|---|---|---|
| `lost` | `FUSECTRL` 读不到 | 该发之后卡不在总线，判决无效 |
| `goldilocks` | 全部检查通过（`FUSECTRL=IDLE`、`DSOV=0`、`CRC=0x55`、`PRIV_MASK=0xffffffff`、FPF 行可读） | 可烧写的窗口 |
| `hit` | `DSOV=0` 且 CRC 有效，其余检查未过 | 落在窗口边缘，不是可烧状态 |
| `under` | `DSOV≠0` | 该位未被扰动 |
| `over` | `DSOV=0` 且 `CRC≠0x55`（含 `0x00`、全 1、`0x75`/`0x57` 这类半截值） | 整块或部分 hash 区未被感知 |

**判官只有一条通路。** 能读 BAR0 的只有插着卡的那台 Linux：板子走 SMBPBI 直读 `DSOV` 的四次读
全部无回执，所以板载判决于 0.4.1 删除（`@P`/`@O` 一并移除，`main/oracle.h` 只留判决词表）。留着一条
从不应答的通路，后果不是"少一个判官"，而是每一发都被它判成 `lost` 并因此推进电压梯子。

**进度只有"反应"一根指标**：`DSOV` 是否从 1 变成 0。`under` 与 `over` 的分布只说明边界位置，不说明接近命中。`over` 与 poison（控制器锁死）之间没有可停靠的中间态：`poison` 是 `over` 的极端形式，向深侧探索时每一发都承担接近对半的概率。

## 二、命中的概率性

命中不是参数解出来的，是在概率分布里抽样。这一点决定所有搜索策略，也决定预算。

### 2.1 三类随机性

| 类 | 内容 | 实测证据 | 处理 |
|---|---|---|---|
| **A 我方时刻不确定** | 计划步到达时刻散布、单笔 PMBus 写阻塞 | `slip_us` 实测 16..268 µs、`reset_slip` 0..245 µs；一笔 16-bit 写 36 µs；0.5.9 实测 `GA_REANCHOR` 前一笔 VOUT 写 `dur` 达 114~309 µs（从机拉伸 SCL） | 与步长同量级 ⇒ 小于约 100 µs 的 `delay` 步长不构成可分辨坐标。固件已消掉主要来源（重锚 + 抬优先级），但残余仍宽于目标窗 |
| **B 卡侧时刻不确定** | OTP 采样在 `PERST#` 释放后多久，每卡不同、不可测 | 三张同 SKU 卡命中坐标各不相同（见下「坐标不迁移」） | 当作每卡常量处理：作为待扫的一维 |
| **C 轨上真实效果不确定** | 同一时刻同一笔命令，因起始轨电压、负载电流、VRM 环路状态，轨上结果每发不同 | 同坐标 `fast=1` 4/4 死、`fast=0` 只是 `under`（轨被保护钳住 = 空 dip）；`writes_failed=0` 却整轮空发 | 每发必测，无参数可吸收 |

判据：一个量值不值得测，看有没有参数能吸收它。固定偏移折进参数；方差做成确定性；只有 C 类必须逐发验证。由此，"同一坐标打出两种结果"是 A 类时刻散布造成的，不是卡的性质。

### 2.2 坐标不迁移

观测按**写窗口轮次**记录（四轮，两个 SKU；轮次不绑定卡的身份，跨烧写认卡靠去掉 SBFE 的 die 指纹）：

| 轮次 | SKU | 命中坐标 | 备注 |
|---|---|---|---|
| 第一轮 | 8 GB | `vd=326`（码 52）、`delay=54`、`3×222` | 第 1 发命中 ⇒ 该位出厂即为 0，不是毛刺的功劳 |
| 第二轮 | 64 GiB | `vd=372`、`delay=64`、`2×222` | 在第一轮的命中点 `326` 上 3 发全 `lost` |
| 第三轮 | 64 GiB | `vd=380`、`delay=84`、`1×222` | 同深度 `3×222` 首发即锁死 |
| 第四轮 | 64 GiB | `vd=372`、`delay=64`、`2×222` | 同坐标当日 200 余发零反应，命中是最后一批的第 2 发 |

两组事实要分开看：**跨 SKU 不迁移**（326 那一组与 372/380 那一组差一个码以上），以及**同一张卡的相邻两轮也可以落在不同坐标**（第三轮 `380/84`、第四轮 `372/64`，按 die 指纹确认是同一张卡）。所以坐标不是参数的解，是分布里的抽样：把别卡坐标、或把上一轮的坐标当先验去做二分，都是在错误的轴上搜索。上游作者的经验值与此一致：**数小时到 48 小时量级、按 die 不同**，即命中是每一发独立的小概率事件。

### 2.3 由此确立的搜索纪律

1. **钉住一个瞄准点反复打**是正确的：A 类抖动使每发有效落点本来就在上百微秒宽的分布里飘，反复打是在分布里抽样。瞄准点取边界浅侧一步——落浅是 `under`（不花钱），落进窗口即命中，只有极少数落太深才 poison。
2. **禁止在已知混现（`under`/`poison` 对半分）的坐标上重复**：那是每发对半作废一个电源周期。
3. **零反应重复不等于必中**：同一坐标长时间 `DSOV` 纹丝不动，说明该坐标对本卡不命中，应换相位档而不是加发数。
4. **搜索轴按 PMBus 码选格**：`366/368/370` 是同一个码 59，`372/374/376/378` 是同一个码 60；300..380 mV 合法区间实际只有 14 个可分辨档。固件自 0.5.5 起按码去重，重复码直接跳过（`phase=exhausted`）。
5. **一个电压点上攒够 `batch` 个判决才挪一格**，网格必须满足 `max ≥ ndelays × batch`，否则整轮塌在一个坐标上（`bench/crack.sh` 开火前拒绝）。
6. **预热坐标 ≠ 战役起点**：预热（建立解锁态与 VRM 状态）用浅档，战役从实测边界起。两者混用会打死卡，导致闸门拒开、整个周期零判决。
7. **致死格首发拿不到判决**：杀死卡的那一发，其后的读数全部落在死亡之后。"该坐标首发即死"是判据，不是数据缺失。

### 2.4 一个电源周期能买到什么

| 事实 | 后果 |
|---|---|
| 每发的时间表自带一次 `PERST#`，收尾那套写（profile OFF→ON）是一次故意的掉电再上电 | **只能打在"已启动完成"的卡上**。同一个动作在 `+128 s` 打卡活，在 `+3.9 s` 打卡死。台架等待条件必须是"卡连续在场足够久"这个事件，不是固定秒数 |
| 逐发 `revert=1`（时间表在 `post+500 µs` 自己写回 `GA_MODE`） | 实测同坐标连打 5/5 存活、每发约 10 s、零主机写。这是当前正解；`revert=0` 让 `GA_MODE` 停在强制导通，第二发踩着自己的残留打 |
| 毛刺会让卡瞬断约 0.3 s 再自己回来 | 单次 config 全 1 读数不能判死，必须连续两次确认（0.25 s 分辨率） |
| 板子在一批打到 `tries` 上限自动 park（实测 12 发） | 每周期发数上限由卡的存活决定，不是 `MAX` |
| 卡死需人工断电 ≥30 s | 断电是不可协商的成本；`lost` 后补一发换来的是 poison（红线） |
| `FUSECTRL=0x00000000`（第三种状态）只需重启判决机（POST 拉一次 `PERST#`） | 该类失败的代价从一次断电降为约 1 分钟重启 |

`host/ga100vfi/shot_policy.py` 是这些节奏参数的唯一出处（读时刻、两档看门狗、串口预算、预热电压、`MODE`），改动必须同时改它的 `why` 并留下测试。

### 2.5 致死维度

| 卡 | 结论 |
|---|---|
| 第一轮（8 GB） | `326` 首发命中，未见致死 |
| 第二轮（64 GiB） | 致死维度是**电压**：码 ≤53 无论 `delay` 一律死；`fast=0` 时同坐标不死（轨道被钳住，属空 dip），说明"必死"只对真毛刺成立。331.25 mV 是硬地板，与暴露时长无关（666 µs 与 222 µs 同样死） |
| 第三轮（64 GiB） | 同一深度上决定死活的是**脉冲数**：`3×222` 两发全锁死，`1×222` 两发全活且第二发命中。累计欠压能量是独立于深度的第二维度 |

`fast=1` 才改变 VRM 保护参数（`PROFILE` 换 `0x32`/`0x30` 等），轨道才真被拉到目标电压。`fast=0` 保留出厂保护，同一坐标是空 dip——这是"参数没动而结果不同"的一类成因。

### 2.6 空发的识别

`pwd=0` 时开火，每一发都在解锁门口返回，`GA_RST_LOW` 不执行，判决是对一张未被碰过的卡回 `under`。识别任一即可：串口 `glitch done ... writes_failed=1`；逻辑分析看 `PEX_RST` 是否真下拉；`ga100vfi/cli.py` 只在 `writes_failed == 0` 时计入判决。**判决数为 0 的一轮不是参数问题，是没有打出去**，两者的排查方向相反。

## 三、VRM 锁状态与解锁序列

判锁态只看 `z` 打印的 `pwd`，即 `STATUS_CML(0x7E) & 0x08`；固件答复的文字不用于判锁态。

| 状态 | 现象 | 处置 |
|---|---|---|
| 无锁 | `pwd=1` | 直接开火，不再发 `u` |
| 故障锁 | `pwd=0`，`z` 能读到 | 先 `CLEAR_FAULTS(0x03)` 再交密码，一发即解，无需断电 |
| 总线无应答 | `z` 报 `ERR status read` | 查接线/地址/供电，与锁无关 |
| 真死 | 清故障后仍 `pwd=0` | 拔 12V + 3V3 ≥30 s |

四条固定事实：

1. **清故障必须排在交密码之前**（`main/main.c: unlock_state()`）。故障闩着时密码被拒，时间线不执行，`GA_CLR` 发不出去，故障永远闩着。
2. **`0x46=0x1229`（config-id）属于解锁，不是可选项**：缺它时 `PEX_RST` 释放后 devinit 立刻把 VRM 重新锁上。写不进去即报 `config-id-0x1229-refused`。脚本不得手写 `0x1228`。
3. **裸打之前不发 `w`**：`w` 把 VRM 交回 PWM-VID，GPU 接管后 `VOUT_COMMAND` 被压制，窗口无法出现。
4. 解锁错误分三类上报（`unreachable` / `password-refused` / `PARTIAL pwd=1 0x46-failed`）。只能给一个字符串的错误报告不许用于硬件结论。

## 四、熔丝控制器：四态与恢复

`host/ga100vfi/classify.py: fusectrl_state()` 是唯一判据函数，判决链、CLI、代理、台架脚本共用。

| 读数 | 状态 | 处置 |
|---|---|---|
| `0xE0040000` | `idle` | 放行 |
| `0xFFFFFFFF` | `unreachable` | 判 `lost`，一发即停（`--max-lost` 默认 1），不补发 |
| `0xBADFxxxx` | `poisoned` | 停手，禁止再读 BAR0，停战役 |
| 其他（实测 `0x00000000`） | `unknown` | 停手；同电压下一发实测为 poison |

两条硬性约束：`unreachable` 必须先于 `poisoned` 判定（`0xFFFFFFFF` 的状态位同为 31）；判定只允许一次 `FUSECTRL` 读，命中危险态后不许"再读一次确认"、不许 `classify`、不许 `capture`。回归锁：`host/tests/test_regressions.py::PoisonGuard`。

固化位置：`classify.py`（第一行读一次即抛 `FuseControllerStop` 子类）、`ga100vfi_agent.py`（停火先于交判决）、`cli.py`（`poisoned_stop`，退出码 4）、`burn.py`（`FuseError`）、`bench/poison_check.sh`、`bench/window.sh` 第 0 步、`bench/crack.sh` 第 4 道门。

恢复顺序（逐级升级，前一级有效就不进下一级）：

1. 板子拉一次 `PEX_RST`：控制台 `j` → ≥2 s → `J`，然后 `bench/poison_check.sh` 重问一次 `FUSECTRL`。真发打出的毒态同样吃 `PERST#`：`0xbadf510e` → `0xe0040000`，device id 同时从 `10de:2080` 回到 `10de:20c2`，不动电源。
2. 重启判决机（POST 拉 `PERST#`，卡与控制器一起走 POR）。
3. `bench/card_probe.sh` 确认重新枚举 → `bench/poison_check.sh` 验 `FUSECTRL`。
4. 卡未回来时先让板子问一次 PMBus（`@r 25 7e 1`）判断卡有没有电。`bench/link_retrain.sh`（对桥 Retrain + rescan）实测 4/4 无效，只当排除桥侧故障的便宜判据。
5. 有电、无链路、软件手段用尽 → 拔 12V + 3V3 ≥30 s（PHY 的 POR）。

三条相关事实：

- **掉链（毛刺后 config 全 1）的卡从不自己回来**：零干预观察 60 s、240 次只读采样无恢复；只有 `PEX_RST` 按住 ≥2 s 再释放能救（约 0.3 s 重新枚举）。而每发时间表本身就带一次 `PERST#`，所以掉链那一发只能靠"再重放一次熔丝链"救回，判决作废——降它只能靠坐标与节奏。
- `10de:2080` 这个 config 指纹是控制器 trip 的信号，**开零次 BAR0** 就能读出，比 `FUSECTRL` 更便宜。
- Gen4 PHY 训练状态与控制器 poison 是两件事，处置不可互抄。

## 五、窗口是易失的

命中之后禁止：发 `r`（`PEX_RST` = 熔丝重采）、加载 `nvidia` 驱动、热重启。取证只走 `bench/window.sh`（全只读 + `CMD_READ`）。窗口未观察到自然到期：关闭只与上述三个动作有关。两次实烧从命中到最后一条记录分别历时约 10 分钟与约 13 分钟，其间每次窗口查询均为 `OPEN`（含中途一次全量交叉对账）。

一次"独立重读 512 行"实测 50 s ~ 2.5 min（熔丝块读速不稳定），估时按 2~3 min/遍。

## 六、FF 烧写

### 6.1 四道闸门（缺一不可）

| 闸门 | 内容 |
|---|---|
| 独立对账 | 两条互不相干的采集路径（本仓库 `ga100vfi.burn capture` 与 ffcalc `ffmacro`）逐行比对，0..486 必须 0 差异；同一遍读重抓两次逐字节一致 |
| 覆盖率 | 行 0..486 完整；`ffcalc mergeff` 报覆盖完整 |
| 认卡 | `ffcalc verify` 通过（UUID 或指纹）。指纹含 SBFE 位，**每次烧写都会改变它**，跨烧写认卡用去掉 SBFE 的 die 指纹；同批卡 defective 相同，指纹本来不是唯一身份证，UUID 优先 |
| 计划自证 | `ffcalc sim` 报 `SIMULATION OK`；`ga100vfi.burn crosscheck` 报 `0 problems`，含目标行现场回读为空白 |

`bench/planmig.sh` 把这四道固化成一个只读入口，并报告"上一轮计划是否原样在场"。

`crosscheck` 独立复核：记录重编码 `record == (new<<16)|(block<<6)|chain` 且 bit5(IFF)=0；清位规则 `new & ~old == 0`；`old` 等于 0..486 按行序回放的 `chain.block` 值且新行号大于被覆盖行号；目标行为空白（空白读 `0x00000000`，不是 `FF`）且同一计划内 `chain.block` 不重复；烧后回放等于计划 `new`；现场再逐行 `CMD_READ` 一次仍为空白。

FF 记录格式：`record[4:0]=chain`、`record[15:6]=block`、`record[31:16]=data`、bit5 必须为 0。FF 行范围 222–486。

### 6.2 顺序与快照语义

1. 试烧 1 条 → 独立重读全表 → 与烧前快照逐行 diff，判据是"**只有该行按记录改变**"。
2. 续烧其余 → 再独立重读 → diff，判据是"计划内的行全部按记录改变、计划外零改动"。`diffrows` 是必做步骤，判据不是"我烧的那几行变了"。
3. 两份快照不可混用：**diff 的起点是烧前那份**（证明计划外零改动）；**续烧的 crosscheck 基线必须是已落地之后的现场**（它要求"声称已续烧的行"在快照里就读作本条记录）。拿烧前快照续烧会被自己的断言拒掉。
4. `burn` 在写之前现场回读计划涉及的每一行：读回既不是空白也不是本条记录的行直接拒绝（往这种行里 PROGRAM 是唯一救不回来的操作）。
5. 单条记录的断言序列（`host/ga100vfi/burn.py`，ffcalc `burntool` 为等价实现）：断言 IDLE/FUSEDEBUG=0/CRC=0x55/DSOV=0 → `CMD_SENSE` 后 DSOV 仍 0 → arm（`SBFE_SHADOW=0`、`WDATA_WR_SECURE=0`）→ 七项授权断言 → `FUSEADDR` 回读 → `FUSEWDATA=record` → `CMD_PROGRAM` → 轮询回 IDLE → `CMD_READ` 回读等于 record。中途出现 `0xBADF…` 或超时立即停手，未烧的行下次窗口继续。
6. `FUSEWDATA` 那条授权断言只在**第一条记录之前**成立：它是写口，上一条写进去的值停在那儿。
7. `EFP_STATUS` 冷启后读 0，发过一次 `CMD_SENSE` 才为 1。`ga100vfi.burn` 在 `arm()` 前自动 `sense()`；ffcalc `burntool` 硬要求 `EFP==1`，刚进窗口时先 `sense`，不要判成"窗口坏了"。

### 6.3 五条与读路相关的事实

1. **`CMD_SENSE` 不刷新 option 影子寄存器**。`SENSE` 只重解析熔丝宏自身影子（EFP/SBFE/CRC/DSOV）；`fbp_disable` 等 option 影子只在 `PEX_RST`/devinit 重算。验证记录是否被采纳必须走 boot。
2. **IFF 区（487–511）在未枚举（VFI）状态下读到的是锁存噪声**，两次独立复现同一签名（20 行不一致），冷启后该区 0 差异。对账一律限制在 0..486，或先冷启再比。`capture_rows` 的默认区间已收至 `FF_ROW_MAX`。
3. **ffcalc 快照磁盘上的行值是 `"0x%08x"` 字符串**，跨实现比对必须先过 `ffcalc.dump.normalize_rows`，否则会把同一数值读成"全表不一致"。
4. 判决机上可能存在第二份 ffcalc 拷贝（旧包无 `__main__`）。跨目录调用要显式钉住 `PYTHONPATH`。
5. 一次毛刺不改熔丝：毛刺后重读全表应与烧前基线 0 行差异。这条本身是判决链与采集路径的自检。

## 七、冷启动验收

`PEX_RST` 让 devinit 重解析 FF 链，等价于完整冷启动；正式验收另做一次整机断电 ≥30 s。入口 `bench/postboot.sh`。

冷启动后读 BAR0 之前先看配置空间 `Command`：无驱动 claim 时 `Command=0x0000`（Memory Space Enable 未置），**BAR0 整片读回 `0xffffffff`**，形状与掉卡不可区分。分岔点是配置空间答不答 `10de:20c2`：答 = decode 没开（`burn wake` 只写该卡 `Command` bit1），不答 = 掉卡。

三条判据：

| 判据 | 内容 |
|---|---|
| A 控制器状态 | `CRC=0x55`、`FUSEDEBUG=0`、`FUSECTRL=IDLE`、无 `0xBADF`、`DSOV=1`（回健康基线）、`SBFE=1`、窗口按预期关闭 |
| B 熔丝保住 | 重读 FF 区与烧前快照逐行比，差异**恰好**是计划内的那些行 |
| C 熔丝真生效 | devinit 重算的 option 影子寄存器等于计划目标，计划未涉及的字段逐位不变；用 ffcalc 这套独立实现现场重算，`gen --mig` 的剩余计划必须为 **0 条**，引擎计数（NVDEC/NVJPG/OFA/SYS_PIPE）读成目标值 |

C 是无驱动条件下"熔丝真生效"的唯一证据面，也暴露它的窄：影子口径只覆盖 GPC/FBP/FBPA 等少数寄存器，`tpc`/`pes`/`fbio`/`nvlink`/`sys_pipe` 那些位只能以 FF 行内容本身作证据。`B` 步的快照存成 `rows-boot.txt`，同一遍重读既喂 diff 也喂 ffcalc。

已知口径差异：影子口径实算 SM 与 `ffcalc analysis` 的 `sm_count` 相差 4（前者是现场缺陷位口径，后者按"目标 = 缺陷位"计算势），引用 SM 数必须注明口径。

## 八、跨轮台账

一个电源周期能买到的发数上限是"到第一次 poison 为止"，因此每轮发数必须累进同一张表：

```bash
bash $HOME/ga100vfi/bench/mkledger.sh    # 汇总所有 *-crack*/agent.log → logs/ledger.txt
```

| 表里看到 | 结论 | 下一轮 |
|---|---|---|
| 全 `under` 且 `DSOV` 从未动 | 该坐标不命中，或时刻未覆盖采样点 | 换相位档（`delay`/`gap`），不要加深或加发数 |
| 全 `over`/`poison` | 太深 | 电压调浅 |
| `under` 与 `over` 混现 | 边界在此 | 钉在浅侧一步反复打，或该电压附近加密 delay 点 |
| `lost` | 卡不在总线 | 该批发数不算数据，先按 §四恢复 |
| `gold` 列为 0 而"合计"比各列之和大 | 有未归类事件，不是命中 | 读原文，别猜 |

台账坐标必须包含波形几何：`(delay, vd)` 两个数不足以复现一发脉冲，`pw/pulses/gap/td/fast/revert` 每一项都改变物理结果。poison 那一发不由代理回传判决，台账按板子记录的坐标补一条事件。

`bench/readtrip.sh` 是判决链自身的排除实验：零脉冲重放判决链的全部访问（含连写三次 `DSOV_SET=1`），`FUSECTRL` 全程 IDLE——判决链的读写不会把控制器打进 poison。

## 九、实烧汇总

本文的判据来自三轮完整的写窗口闭环（两个 SKU：8 GB 与 64 GiB）。这里只留能迁移的结论，逐卡现场档案不进仓库：一次窗口的产物（快照、计划、crosscheck、逐行 diff、冷启动读数）按运行目录保存在判决机 `$HOME/ga100vfi/logs/` 下，要留的证据从那里取。

| 观测 | 数据 | 用法 |
|---|---|---|
| 命中坐标 | `326/54/3×222`、`372/64/2×222`、`380/84/1×222`——三组互不相同；同一物理卡的第二轮命中落在与第一轮不同的坐标上 | 只当作搜索起点，不当先验（§2.2） |
| 概率样本 | 一轮在同一坐标当日 200 余发零反应，命中出现在最后一批的第 2 发；判到即停火，未补发 | 预算按"一个下午"计，不按"一次实验"计 |
| 计划规模 | 3~16 条记录，行号 297–314，行号一律由 `gen` 按该卡现场算 | FF 行是一次性资源：已用行数就是该卡的剩余空间 |
| 冷启后的共同形状 | `CRC=0x55`、`DSOV=1`、`SBFE=1`、窗口按预期关闭、`gen` 剩余 0 条 | §七 的 A/B/C 三判据 |
| 认卡 | 整串指纹每次烧写都变（它含 SBFE 位）；去掉 SBFE 的 die 指纹跨烧写稳定 | 计划归属断言用后者 |

上游样本给出的收益与代价，属其结论，本仓库不担保（[原文](https://blog.kate.land/posts/using-voltage-glitching-to-unlock-the-a100/)）：8 GB SKU 约十之九可到 80 GiB；SM 常见 >120，吞吐约 1.2× 零售 A100；Gen4 x16 需换耦合电容；NVLink 需桥接 PCB 上缺件的 U11；ECC / MIG / NVDEC / NVJPG 在其文中是"可解锁但未验证"。本仓库验到的止于 devinit 重算的 option 影子与引擎管道计数（NVDEC/NVJPG/OFA/`SYS_PIPE`）；驱动层几何与链路重训见 [CMP170HX解锁经验与踩坑总结.md](CMP170HX解锁经验与踩坑总结.md) 与 cmpunlocker。

## 十、已推翻的结论（保留作判据）

| 不成立的结论 | 事实 |
|---|---|
| 判决全 `under` ⇒ 电压配方不对 | 该轮 20 发全为空发（`writes_failed=1`） |
| VRM 闩死必须拔 VDD33 ≥30 s | 故障锁一发即解（先 `CLEAR_FAULTS` 再看 `pwd`） |
| 毛刺把卡打坏了 | `dead`/掉链的后果是"掉链且必须整机断电"；断电后 `CRC=0x55`、`DSOV=1`，512 行与烧前基线逐行相同，熔丝一位未动 |
| `CLEAR_FAULTS` 能救掉链的卡 | `STATUS_BYTE`/`STATUS_OTHER` 清零后卡仍不应答、`PEX_RST` 仍叫不回；不是 VRM 闩锁 |
| 「一个电源周期只买得到一发」是物理规律 | 成因是收尾写落在启动过程中。逐发 `revert=1` 后同周期连打 5 发全活 |
| 「15/15 全发生在第 2 发」⇒ 第二发必死 | 该统计同时混淆了"第二发"与"打完还没恢复透"两个变量 |
| 码 ≤53 必死，与 `delay` 无关 | 只对 `fast=1` 成立；`fast=0` 时轨道被钳住，同坐标只是 `under` |
| `DSOV=1` 是"下拉太浅" | `DSOV` 是熔丝位 `OPT_DISABLE_SW_OVERRIDE`；`under` 的正确读法是"这一位还是 1" |
| 标定区浅边界（`vd=380`）在安全一侧 | 第三轮在 `380` 上 `3×222` 首发即锁死；且 `MAXV` 默认 384，`VD>384` 会被整批拒。固件硬范围 0..1000 mV，380 只是 campaign 默认上沿 |
| 族冻结的键（`pw × 相位档`）足以描述致死 | 同族同深度 `3×222` 死、`1×222` 活：键里缺 `pulses` |
| 毛刺后重读 512 行即可做烧前/烧后对账 | VFI 态下 487–511 是锁存噪声，对账限制在 0..486 |
| 冷启动后 BAR0 读回全 `0xff` ⇒ 卡已死 | 无驱动 claim 时 `Command=0x0000`，`wake` 后 `PMC_BOOT_0=0x170000a1`。配置空间仍答 `10de:20c2` 时不判死 |
| 同坐标同波形打出两种结果 ⇒ 卡的性质 | 是时刻散布与 `delay` 步长同量级造成的判据自证 |
| 零反应的坐标继续加发数会命中 | 命中是每发小概率事件，但坐标本身不命中时加发数不买命中；换相位档 |

共同点：每一条都源于跳过判据直接下结论。每条现在对应一个脚本、一段断言或一条测试。
