# 0.2.0 架构与协议说明

本页描述当前源码行为。它不包含目标固件编译或实板认证声明。引脚由 [board.h](../main/board.h) 定义，构建入口见 [BUILD.md](BUILD.md)。

## 硬件操作所有权

`main.c` 创建固定在 core 1、优先级 8 的执行任务。UART 和 HTTP 先提交完整命令，执行任务再按顺序处理。自动流程使用 `campaign_poll()` 协作式状态机，不另建一个任务同时操作总线。

队列以完整命令为单位，单条最多 255 字节，不包括 C 字符串终止符。超长、不完整、含 NUL 或内部换行的网页命令会被拒绝；UART 超长行会丢弃到行末，不会执行截断后的内容。队列满时返回错误，不静默丢掉半条命令。

自动流程运行时，手动硬件操作被拒绝；状态查询和流程停止仍可使用。停止请求会在当前同步操作结束后处理，不承诺中断一笔已进行中的 I²C 事务。停止或失败结束会尝试恢复控制器，`restore_ok` 报告恢复结果；成功结束不再额外复位或执行自动恢复。

OTA、网页 Wi-Fi 凭据写入和硬件执行共用维护锁。后台日志及状态快照另外同步，不允许读到新序号搭配旧结果字段。

## 时间与采样

复位仍由软件时间表执行。阻塞式 I²C、驱动调用和调度会造成迟到；移到单一任务并不消除这些误差。

- `slip` / `board.last.slip_us`：时间表步骤开始执行时的最大迟到量。
- `reset_slip` / `board.last.reset_slip_us`：实际复位释放操作的时间戳与计划零点的差。

有效总线速度在初始化与上拉检查后确定。状态中的 `requested_baud` 是请求值，`baud` 是用于设备配置和时间预算的有效值。理论事务时间只提供下限，不构成时序保证。时序限制详见 [CALIBRATION.md](CALIBRATION.md)。

## 串口兼容

原有单字符命令保留：`v u z w k K r j J b`。`g ...` 和 `@...` 是以 CR 或 LF 结束的行命令。主机客户端现在等待完整结束行，不会仅收到 `glitch done` 前缀就停止接收。

常用状态与管理命令：

| 命令 | 当前行为 |
|---|---|
| `v` | 输出板卡状态 |
| `z` | 读取控制器状态 |
| `@W` | 查看网络状态；网页支持包含空格或特殊字符的独立 SSID/密码 |
| `@O` | 查看当前判决模式 |
| `@O 0` / `@O 1` | 空闲时选择 SMBPBI / 手动或主机代理模式 |
| `@C status` / `@C` | 查看自动流程状态 |
| `@C stop` | 请求停止自动流程 |

`@C start` 的选项仍使用 `key=value`。数值严格解析，未知字段、溢出和超出边界的配置会返回错误。`delay=` 列表使用独立解析状态，不再吞掉之后的选项。`max` 是总尝试上限；`max=0` 表示不限总次数，多点配置按点轮转。

原有完成行字段保留，并追加诊断字段：

```text
glitch done pwd=... e1=... writes_failed=... slip=... reset_slip=... diag_ok=...
```

遥测输出位于结束行之前。`diag_ok=0` 表示尝试后的诊断读取不完整；`writes_failed=0` 本身不能覆盖这类失败。准备或参数错误使用 `glitch ERR ...`，一般命令错误使用 `ERR ...`。

软件边界定义在 [glitch_plan.h](../main/glitch_plan.h)，用于防止非法参数、溢出和不完整计划，不是针对任意外部设备的电气安全保证。

## 自动流程与判决关联

每次启动创建新的非零 `session`；每次尝试递增 `attempt`。当前流程的模式固定，忙时启动失败不会偷偷修改模式。

关键状态字段：

| 字段 | 含义 |
|---|---|
| `running` / `phase` | 流程是否仍运行及当前阶段；恢复阶段仍保持 running |
| `session` / `attempt` | 当前会话和尝试编号 |
| `sequence` | 对应板卡完成记录的序号；尚未完成时为 0 |
| `awaiting_verdict` | 当前是否允许提交这一轮的外部结果 |
| `tries` / `valid` | 已发起尝试数 / 有可用分类结果数 |
| `nack` / `lost` / `timeouts` | 执行或通信失败 / 设备不可读 / 外部判决超时 |
| `restore_ok` | 结束恢复是否成功 |

外部结果必须同时携带 `session`、`attempt` 和 `r`。过期编号、未知结果、错误模式或非等待阶段会被拒绝。对最近一次已接收的相同结果重试可获得确认，不会重复累计。结果提交的响应体为 `ok`；不匹配返回 HTTP 409。

主机代理保留未确认结果并重试网络提交，避免为重试再次执行会访问寄存器的分类。停止、重新启动或轮次变化后，旧结果被丢弃。

SMBPBI 路径检查各笔读写结果，将不可用读取计为 LOST。原有帧格式仍属于待目标卡验证的实现，不能仅凭离线替身测试视为协议已验证。

## HTTP 错误处理

`/api/cmd` 按 `content_len` 完整接收，再统一提交命令。过长请求返回 413；收包失败不执行已收到的前半段。错误连接不会在残留请求体未消费完时复用。

Wi-Fi 参数先 URL 解码，再按独立的 SSID 和密码验证、保存，避免空格分隔和百分号编码破坏凭据。NVS 擦除后的重新初始化及保存错误会被处理。OTA 检查镜像写入、结束验证和启动分区选择的返回值。

## 重启记录

运行记录放在 `RTC_NOINIT_ATTR` 区，带有效性标记。启动先读取上一轮记录，再清理本次状态。断电或无有效保留记录时不会伪造历史阶段。

50 ms 的 `esp_timer` 回调在时间表执行阶段监视心跳；心跳超时会释放复位线并请求重启。它不替代硬件测量，也不能保证 MCU 重启后外部电源控制器自动恢复。
